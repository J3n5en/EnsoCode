# ChatGPT 账号池顺序接替

## 行为差距与范围

现有订阅模型绑定单个 `oauthAccountKey`，该账号额度不足时，即使其它账号仍有额度，主会话或子代理也会结束为失败。第一版增加显式启用的 ChatGPT 自动接替条目，固定账号与 API Key 条目保持原行为。

- 使用当前账号直至确认不可用，再按配置顺序选择下一个符合条件的账号；不逐请求轮询。
- 只使用已配置、启用、已登录且支持所选模型的池成员，不改变模型或推理档位。
- 主会话与子代理共享池状态。并发报告同一失效账号不得导致连续跳过多个账号。
- 在任务失败结算前恢复同一会话，不重新派发整个任务，不重放已完成的工具。
- 用户取消、会话释放及全部成员不可用时停止恢复，不产生无限重试。

## 所属层与文件

| 层 | 文件或模块 | 职责 |
| --- | --- | --- |
| Shared | `types/llm.ts`、`types/agent.ts`、`defaultModel.ts`、账号池纯策略 | 配置、协议校验、成员有效性与错误分类 |
| Main | `services/agentHost.ts`、账号池服务 | 从权威配置验证成员、统一当前账号与冷却状态、处理 worker 请求 |
| Worker | `supervisor.ts`、账号池 SDK 适配 | 路由实际账号，在终态结算前继续未完成请求 |
| Renderer | 模型服务设置、模型选择器及状态展示 | 显式创建自动接替条目，区分池与固定账号，避免显示错误账号的额度 |

`ModelProvider.oauthAccountPool` 保存有序账号键；未配置该字段表示固定账号。配置的逻辑模型身份与实际执行账号分开，子代理允许列表不因账号接替而改变。

## 错误与恢复约束

PI SDK 的默认重试并不包含所有额度错误，不能仅依赖虚拟模型的 `retry` 路由。应使用公开的请求路由与结算前扩展边界，避免依赖私有会话修改方法。

上游可能将普通限流与额度耗尽归一为同一文案，因此文案不是长期冷却的充分证据。额度窗口查询失败代表未知；认证失效与额度耗尽须区分，普通网络故障不得将整个账号池标为耗尽。

第一版仅对账号池会话使用 SSE 传输，以在 SDK 文案归一化前提取结构化错误证据；固定账号保持原来的传输选择。账号池暂不使用 WebSocket 续接优化。Main 当前账号与冷却信息为进程内状态，应用重启后重新按配置顺序选择，并非持久化额度账本。

恢复必须保留成功工具及其结果；若失败响应与已执行工具交织，不能通过删除整个回合或重发原始用户消息恢复。部分流输出和取消竞态需要专门回归。

## 明确不做

- 不支持其它订阅厂商的自动轮换，尤其不放开当前 Cursor 适配的单账号限制。
- 不自动转 API 付费、不跨模型降级、不引入代理服务器。
- 不迁移用户现有固定账号配置，不访问真实账号来主动耗尽额度。

## 验证要求

先用失败测试固定策略和边界，再实现。使用隔离假凭据、假 provider 和真实 SDK 验证 A 耗尽后 B 完成同一任务、工具仅执行一次、并发去重、取消不复活、池耗尽有界结束，以及固定账号/API Key 回归。界面使用隔离数据验证；模拟结果不等同真实 ChatGPT 额度耗尽验证。

## 本次验证记录

- 真实 PI SDK 配合假 provider 的 12 项测试通过，包含工具只执行一次、同任务接替、原生 OAuth 刷新失效、普通网络错误不换号、动态成员、冷却到期仍有界结束及取消。
- 账号池策略、Main 权威成员校验、协议、实际账号额度及模型菜单的相关回归测试通过。成员邮箱修复另经 19 项设置界面及账号池测试验证。
- 类型检查、定向格式检查（保留现有 CRLF）和变更差异检查通过。最近一次全库测试为 6336 通过、93 失败、15 跳过，失败尚未完成上游基线归因，不宣称与本次改动无关。全库 Biome 尚未通过，未进行全库格式化。
- 隔离 Electron 实例验证了创建池、成员编辑、默认模型选择及重启后配置保留；实际账号提示使用真实组件与合成事件检查画面，不代表真实额度耗尽接替。
- Windows x64 安装包构建成功。用户已在 Windows 上完成安装及手动测试，确认账号池成员邮箱、自动接替选项及实际账号额度显示正常。
- 未进行真实模型额度耗尽后的完整接替或跨厂商真机验证。首次请求前或重启后尚未恢复实际账号记录时，额度可能暂不显示。隔离测试进程和测试账号数据已清理。

配置同步不会迁移设备本地账号池成员；匹配已有本地条目时保留本地配置，新导入的无凭据条目禁用。
