本地模型目录与价格目录结构、Google 最新模型缺失原因调查报告

一、核心结论摘要

1. “模型目录”与“价格目录”是否为同一个概念？
   结论：它们不是同一个概念，但依赖同一个底层数据源。
   - “模型目录”（Model Catalog）：指系统运行时通过 runtime.getModels() 获取的全量模型实体定义。包含模型标识（id）、展示名称（name）、API 协议类型（api）、所属提供商（provider）、推理能力（reasoning）、思考档位映射（thinkingLevelMap）、上下文窗口（contextWindow）、最大输出（maxTokens）以及计费费率（cost）等全方位元数据。
   - “价格目录”（Pricing Table）：指专用于用量核算与费用计算的内存单价映射表（Record<string, ModelPricing>）。它是由 usageService.ts 的 buildPricingTable 函数从“模型目录”中抽取具有非零有效 cost 字段的模型衍生生成的纯单价表。
   - 区别与联系：
     a. 数据源相同：价格目录派生自模型目录中的 model.cost。
     b. 覆盖范围不同：所有按月包月/订阅制模型（如 google-antigravity、cursor）在模型目录中 cost 均为全 0，会在生成价格目录时被显式过滤排除；未在官方/代理 API 提供商清单中配置有效 cost 的模型不会进入价格目录。
     c. 查询逻辑不同：价格目录在查表时会通过正则表达式剥离思考档位后缀（如 -high、-medium）再次回退查找基底模型，而模型目录的精确反查默认按严格 id 匹配。

2. 截图中各模型无单价 / 有单价的原因：
   - gemini-3.8-flash-high：
     链路：通过 Google Antigravity 扩展提供商（或 Cloud Code Assist 动态模型发现）产生的会话，记录在 JSONL 中的模型 id 为 gemini-3.8-flash-high。
     根因：
     (1) 剥离思考档位后缀 -high 后基底模型为 gemini-3.8-flash；
     (2) 底层内置模型目录（node_modules/@earendil-works/pi-ai）中收录的 Google 官方按量计费模型最高只到 gemini-3.7-flash，完全不存在 gemini-3.8-flash 条目；
     (3) Antigravity 属于订阅提供商，在注册时所有模型均硬编码为 ZERO_COST，被 toPricing 函数直接过滤，不向价格表提供单价；
     (4) 最终 resolvePricing 查无单价返回 null，被 aggregateUsage 归入 unpricedModels 并由 UI 提示。
   - gpt-5.6-sol：
     在 azure-openai-responses、cloudflare-ai-gateway、github-copilot、openai、openai-codex、opencode 等多个官方/中转提供商的模型目录中均有收录，且带有有效非零 cost 费率（如 input: 5, output: 30 $/M tokens），因此能正常计费，不会报缺少单价。
   - imported：
     来自第三方会话导入功能（src/main/services/sessionImport/piJsonl.ts:35）。当导入外部会话未指定原始模型名称时，代码默认将 model 写入为 "imported"。该字符串并非真实模型 ID，模型目录与价格目录中均无对应项，因此被正确识别为无单价模型。

五、Google 官方模型命名、价格与当前本地目录差异对比

1. 官方 API 模型命名规律：
   - 官方公开 API 模型通常采用标准主版本号与次版本号组合，如 gemini-2.5-flash、gemini-2.5-pro、gemini-3-flash-preview、gemini-3.1-pro-preview 等。
   - 包含思考模式（Thinking）的官方模型，在标准 API 下通常是通过请求参数中的 thinking_config 启用，或以专有预览后缀区分，而非直接在模型 ID 后面拼接 -high、-low。
   - 带 -high、-medium、-low、-tiered、-agent 等后缀的名称，是 Google 内部 Cloud Code Assist（即 Antigravity 后端）使用的专有路由名称（wire id），或是部分聚合中转站为了映射思考强度档位而人为拼装的别名。

2. 为什么当前本地目录中没有 gemini-3.8-flash？
   - 数据来源层：本地模型目录的静态生成源为 @earendil-works/pi-ai 包（版本 0.84.3）。在该版本打包发布时，Google 官方对外公开的模型和预设清单中最高只发布到了 gemini-3.7-flash。
   - Google 已于 2026-09-02 正式发布按量计费的 gemini-3.8-flash，并公布初次体验价；但该发布时间晚于本地 pi-ai 0.84.3 和 npm 最新 0.84.4 的发布时间，因此两个版本的静态目录都还未收录。
   - Antigravity 运行中动态通过 fetchAvailableModels 获取到了带 thinking 档位的 gemini-3.8 wire id（如 gemini-3.8-flash-high），因此它出现在会话记录中；但 Antigravity 条目为 0 单价且会被价格目录过滤，而静态公开 API 目录又尚未同步 3.8，导致价格目录中无对应单价。

六、最小方案建议与用户确认事项（不修改产品代码）

1. 关于 gemini-3.8-flash-high：
   - 若用户期望计入估算费用：可使用 Google 已公布的 gemini-3.8-flash 初次体验价（截至 2026-12-31 输入 $0.75/M、输出 $3.75/M）作为本地补充价格；npm 当前最新 pi-ai 0.84.4 同样早于 3.8 发布，单纯升级仍不能补齐。
   - 若用户仅希望避免无单价警告打扰：可以在用量页面针对订阅提供商（如 google-antigravity、cursor）产生的纯订阅记录进行标识区分（例如标为“订阅包含”而非“缺失单价”）。

2. 关于 imported：
   - PRD 明确要求“不为 imported 这类非模型 ID 猜测价格”。
   - 建议在未来代码改动中，对历史导入会话（model === 'imported'）在用量 UI 上做特殊标记或静默归类为“外部导入（无用量明细）”，避免将其当作缺失单价的真实模型展示在警告条中。
