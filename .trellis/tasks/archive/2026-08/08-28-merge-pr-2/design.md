# 合并设计

## Boundary

本任务只操作 GitHub PR #2 的审查与合并状态。工作区用于读取当前头提交和运行门禁，不产生业务代码改动。

## Review Contract

- 静态门禁与安全/质量复审并行，均以当前 PR 头提交为基准。
- 静态门禁负责类型检查、测试、格式/静态分析及其基线归因。
- 复审负责跨层数据流、权限/资源上限、持久化边界和本轮差异风险；输出 P0/P1/P2，并区分本轮引入与存量。
- 任一路存在本轮引入的 P0/P1，合并立即阻塞。

## Merge Contract

- 合并前重新读取远端 PR，防止审查期间头提交变化。
- 仅使用 GitHub PR 合并能力，目标为 `dev`；不在本地制造或推送合并提交。
- 合并后以远端 PR 状态和 merge commit SHA 作为完成证据。

## Safety and Rollback

- 不暂存工作区文件，避免纳入 `.trellis/workspace/imhuso/` 与 `out-qa-9333/`。
- GitHub 合并是不可逆的远端写操作；若门禁或远端状态异常，不尝试强制合并。
- 合并后发现问题需走独立回滚/修复 PR，本任务不自动改写 `dev` 历史。
