# 执行计划

1. 读取 PR 当前头提交、远端检查状态与可合并状态，记录审查基线。
2. 同一批次并行派发：
   - 测试角色执行完整静态门禁，保留命令、退出码和基线归因证据。
   - 评审角色执行合并前安全/质量复审，确认本 PR 引入的 P0/P1 为零。
3. 汇总两路证据；任一路不放行则停止合并并报告阻塞项。
4. 放行后再次读取 PR，确认头提交未变化且仍可合并。
5. 通过 GitHub PR 接口合并到 `dev`。
6. 读取远端 PR，确认 MERGED 与 merge commit SHA；检查本地未跟踪目录仍未被纳入版本控制。

## Validation Gates

- 静态门禁使用项目现有命令，不跳过测试，不修改业务文件。
- 安全复审覆盖 main/preload/renderer/shared 跨层契约、IPC 输入边界、资源上限、持久化水合与凭证删除路径。
- 远端 PR 头提交与审查基线不一致时，审查作废并重新执行。

## Rollback Point

GitHub 合并动作之前均可无副作用停止。合并动作之后不改写历史；异常通过后续 revert/fix PR 处理。
