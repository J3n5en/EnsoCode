# 国际化规范

## 翻译键就是英文原文

没有 `common.button.save` 这种键名体系。`src/shared/i18n.ts` 里
`zhTranslations` 的 key 直接是英文文案：

```ts
export const zhTranslations: Record<string, string> = {
  'Model Providers': '模型服务',
  'Import from local apps': '从本地应用导入',
  'Fetched {{count}} models': '拉取到 {{count}} 个模型',
};
```

`getTranslation()` 查不到就原样返回 key，所以**英文缺翻译不会崩，只是显示英文**。
这也意味着：改英文文案等于换了一个 key，必须同步改 `i18n.ts` 里的条目，
否则中文界面会悄悄退回英文。

## 用法

```tsx
const { t } = useI18n();

<h3>{t('Model Providers')}</h3>
<span>{t('{{count}} models', { count: provider.models.length })}</span>
```

插值用 `{{name}}` 双花括号。需要在文案中间嵌入 React 节点时用 `tNode()`
（返回 `React.ReactNode`，见 `src/renderer/i18n.ts`）。

## 新增文案的规则

- 用户可见的字符串**一律**过 `t()`，包括空态提示、错误信息、按钮、徽章。
- 英文原文写完整句子或明确短语，不要写缩写或占位符。
- 立刻在 `src/shared/i18n.ts` 补中文，不要留到"以后再说"。
- 中文翻译保持与仓库其它文案一致的语气：简洁、陈述、必要时说明代价。
  例：`'Saving overwrites {{path}} directly — {{source}} will pick up the change.'`
  → `'保存会直接覆盖 {{path}} —— {{source}} 会随之生效。'`

## 语言判定

`normalizeLocale()` 只看是否以 `zh` 开头，其余一律 `en`。
默认取 `navigator.language`，用户可在设置里改，存 `settings.json` 的 `language`。

切换语言会同时设置 `document.documentElement.lang`（在 `applySettings` 里），
新增语言相关副作用要写在那里才能多窗口同步。

## 不要做的事

- 不要在主进程里翻译。主进程返回**原始英文错误信息**或结构化错误码，
  由渲染层决定怎么呈现（见 `providerApi.ts` 的 `toMessage`）。
- 主进程里少数面向用户的展示名（如 `SOURCE_NAMES` 的 `'Claude Code 插件'`）
  是数据不是文案，直接写中文即可，不走 i18n。
