# 回退+文件后文件没有恢复

## 症状

「回退+文件」点了没报错,对话正常回退,但工作树文件纹丝不动。单测全绿,
单会话手测也正常,只在真实使用中复现。

## 根因

checkpoint 的 spawn 期清理最初是「删掉所有非当前会话的 refs」(照搬 pi-rewind——
它是单会话 CLI,该语义成立)。enso 是多会话应用:**同一个 git repo 下多个会话并存,
任何一个会话 spawn(含切换对话触发的自动 resume)都会把其它会话的快照全部抹掉**。
用户回退时快照已不存在,restoreForEntry 无命中走「静默降级为仅对话」分支——这个
为非 git 项目设计的优雅降级恰好把故障也吞掉了。

## 修法

清理改按时限:`pruneStaleCheckpoints(root, maxAge=7d)` 只删过期快照,不看会话归属
(`src/agent/checkpoint/core.ts`)。每会话数量上限(50)仍在创建时裁剪。

## 教训

1. **vendor 单实例工具进多实例宿主时,逐条审视「全局清理」类逻辑**——单会话语境的
   "cleanup others" 在多会话下就是互相破坏。
2. **静默降级会掩盖故障**:同一个 no-op 分支既服务「非 git 项目」也吞掉了「快照被误删」。
   降级分支要能区分「预期内不可用」与「该有而没有」,后者至少要留日志。
3. 单测覆盖不了跨会话交互;这类问题用 CDP 连 dev 实例做端对端最快复现
   (dev 版 renderer 开着 9222,`window.__stores` 暴露了 zustand store 可直接驱动)。
