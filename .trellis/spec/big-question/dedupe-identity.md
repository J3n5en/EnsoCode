# 去重要按"什么算同一个"来定义

## 症状

技能扫描导入后，同一个技能出现了三份 —— `agents-sdk`、`cloudflare`、`wrangler`
等 11 个技能各来自 `~/.claude/skills`、`~/.codex/skills`、`~/.cursor/skills`，
`SKILL.md` **内容逐字节相同**，只是路径不同。

去重逻辑明明写了，却一条都没拦住。

## 根因

指纹选错了。当时技能的去重键是**目录绝对路径**：

```ts
const skillKey = (target: string): string => path.resolve(target);
```

三个副本路径各不相同，于是被当成三个不同的技能。

同期 MCP 的去重是好的 —— 它用的是启动命令而不是名字，
所以 `semble` 在 Claude 和 Cursor 里配置重复时被正确识别。

## 修法

按各类资产**真实的身份定义**选指纹：

| 资产 | 指纹 | 理由 |
|------|------|------|
| 模型服务 | `baseUrl + apiKey` | 同端点同钥匙就是同一个服务 |
| 技能 | **名称**（小写） | 技能按名称调用，同名无法共存；同一技能常被多个工具各装一份 |
| MCP 服务器 | 启动命令 + 参数，或 URL | 名字各家不同（`cunzhi` / `寸止`），命令才是身份 |
| 指令文件 | **内容 SHA-256** | 文件名相同内容各异（多家的 `AGENTS.md`）；内容相同文件名各异（`CLAUDE.md` 与 `AGENTS.md` 常是同一份） |

改成名称去重后：59 条技能 → 37 个唯一名称，被标记的 22 条正好是那 11 个三重副本。

**换指纹前先验证不会误伤**：当时先统计了全部 59 条的名称分布，
确认插件技能和独立技能之间零撞名，才敢改。这个验证只花了一条命令。

## 三层都要拦

```
扫描时   assetScan/index.ts  标记 duplicated + duplicateReason
确认导入 collectAssetImport  批内按指纹去重
落库前   store 的 addXxx     再判一次，防止强制重复导入
```

只做其中一层就会有漏网路径：比如用户手动勾选了标灰项，或反复点导入。

## 重复项要标记而不是丢弃

候选带 `duplicateReason`，界面区分三种文案：

| 值 | 文案 | 含义 |
|----|------|------|
| `registered` | 已存在 | 库里已经登记过 |
| `same-content` | 内容相同 | 与本轮更靠前来源的条目内容一致 |
| `same-name` | 同名 | 技能重名 |

早期只有一个"已存在"，导致用户看到 Codex 的 `AGENTS.md` 标着"已存在"却
在库里找不到它 —— 因为它其实是"和 Claude Code 那条内容相同"。
**措辞要说清是哪一种重复**，否则用户无法判断该不该手动勾选。
